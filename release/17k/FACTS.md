# 17k release facts (17k-r2)

17k-r2 (rebuilt 2026-11-07; supersedes the unflashed r2 with vendor `3a70f811`) = the first 17k + B22 `port-netguard` + B24/B25b slider hold (`port_sliderdex`, `port-slider-hold.dex`) + B26 audio policy `primary input` maxOpenCount 1 in the vendor image + a non-fatal restricted_networking_mode step in the installers. Only `vendor.img` changed; every other image is byte-identical to the first 17k. **Never flashed or boot-tested.** The writer of `restricted_networking_mode=1` is unknown: the guard is defensive, not a root-cause fix.

## Target and behaviour

- Target: OnePlus 7 Pro GM1910 / PLK110 (`guacamole`; the bootloader reports fastboot product `msmnile` on the author's phone), ColorOS 17 PLK110 donor on the LineageOS 24 vendor and kernel.
- Build 17k = 17j-r2 (system/my_stock/boot unchanged, incl. the B18 wallpaper-saver fix) + B20 charging-limit enforcer + B21 real-gauge level in the vendor image ([docs/CHANGELOG-17k.md](docs/CHANGELOG-17k.md)).
- Installers (installer revision 2026-11-07, new in 17k-r2): default = UPGRADE, no data wipe. They detect the mode first (exactly one device in `adb devices` or `fastboot devices`), no longer ask for GM1910/PLK110, flash the active slot's `vendor`, `system`, `boot`, then ask "Wipe user data? Default is No: upgrade keeps your data. Type WIPE to erase /data." before the final reboot. Only the exact word `WIPE` (or `--wipe` / `-Wipe`) runs `fastboot -w`; Enter, other text, EOF/piped input without the word, or `--no-wipe` keep the data. Android mode keeps the guacamole / port-installed / active-slot / free-space / root checks and stages `my_stock.img` (SHA-256 verified, old one kept as `my_stock-prev.img`) before rebooting to the bootloader. Bootloader mode reads `fastboot getvar product`: `msmnile` continues, anything else warns (reported vs expected) and needs a typed `yes` (or `--confirm-device`), otherwise nothing is written. Pure bootloader mode and every WIPE copy `my_stock.img` after the first boot (NoRoot: temporary bootstrap system with adb root, as the 17d clean install; Magisk: MagiskSU on the final system, as the 17d Magisk clean install); /data is wiped, so a copy staged before is erased and redone. The packager now requires exactly one `fastboot -w` call per installer and refuses any fastboot erase/format. **The new logic was tested only with stub adb/fastboot scripts (`logs/installer-stub-test.txt`); it was never run on a phone, and the wipe path (a wiped phone, first boot, adb authorization, Magisk root grant) has never run at all.**
- Final system (both bundles): production properties (`ro.secure=1`, `ro.debuggable=0`, `ro.adb.secure=1`), no builder ADB key. `bootstrap-system.img` (NoRoot bundle only) = the development build with adb root.
