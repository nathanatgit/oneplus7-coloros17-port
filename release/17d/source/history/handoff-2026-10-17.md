## 8. Auto-brightness curve (investigated 2026-10-17, live-fixed, baked for build 17, not flashed)

Finding: the missing `ro.oplus.display.brightness.xs/ys` keys are **not** the problem. ColorOS 17 only reads `ro.oplus.display.brightness.xs` as a "curve prop" label (`OplusDisplayDeviceConfig.mBrightnessCurveProp`, default `unknow`); the real lux->nit curve is built into oplus-services (dumpsys shows `BrightnessConfig luxId=-1`, empty lux/nit tables, so the `lux_table`s in `display_brightness_config_common.xml` are unused here: remapping them live had no effect). The mismatch is in the **nit -> level table** (`/system_ext/etc/display_brightness_config_default.xml`, donor panel: level 8191 = 487 nit).

Measured: manual slider level L -> `panel0-backlight` raw = L/10 (222->23, 4093->409, 8191->818; 10239 -> 1023). Auto mode at ~100 lux gave raw 376-410 on the donor table; H.40 stock curve gives 221. H.40 `ys` / ColorOS17 nit curve = 2.52-2.7 at every sampled lux (8, 16, 36, 100, 260, 1000, 2000), so the 7 Pro's panel runs ~2.55 raw per nit.

Fix: nit(level) = level/10/2.55 in the default table (`tools/live/brightness/rescale_nits.py`, output `display_brightness_config_default.h40nits.xml`, sha ae420be1...). Live: bind-mounted over `/system_ext/etc/display_brightness_config_default.xml` + `setprop ctl.restart zygote`; at lux 103 panel raw = 223 (H.40: 221). Baked in `tools/build-port-b.sh` (donor sha assert 0cf4765e...) and `tools/preflight-b.sh`.

Caveats: only ~100 lux was re-measured after the change (room light); high-lux/HBM behaviour untested (targets above ~400 nit clamp at level 10239). The 2.55 ratio assumes H.40 and ColorOS 17 intend the same nits; no photometer check. Light-sensor ~0.45x lux scaling is separate and still open. Live state lost on reboot.

### 9c. Voice wake-up (Breeno) deep dive, 2026-10-17

Live-tested by re-enabling `com.oplus.ovoicemanager.wakeup` (the switch then opens; the package is disabled again afterwards, wireless adb <LOCAL_IP>:5555).

1. Original failure: `sound_trigger_hw: stdev_load_sound_model: no matching vendor uuid found` -> `loadPhraseSoundModel_2_1 (code -22/5)`. ### 12b. ROOT CAUSE FOUND: wrong eSE power GPIO in the LOS dtbo; eSE now works (15:24)

- Stock `dtbo.img` (H.40) nfc node: `nxp,pn544-ese-pwr = <&tlmm 49>` (0x31); the LineageOS `dtbo.img` (LineageOS24/) still has the Qualcomm reference `qcom,nq-esepwr = <&tlmm 42>` (0x2a). - Test kernel quirk in `drivers/nfc/nq-nci.c` (patch `research/ese-p73/port/los-nfc-p73.patch`): if ese_gpio == en_gpio+1 use en_gpio+8 (TLMM 49).
