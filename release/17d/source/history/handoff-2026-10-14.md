## 1. Where things stand right now

- **Device:** OnePlus 7 Pro GM1910 (`guacamole`), bootloader unlocked, ADB serial `<DEVICE_SERIAL>`.
- **Slot B (active)** = the port, test build "PLK build 6":
  - `boot_b`  = `out-plk-debug/boot.img` (LineageOS 24 kernel+ramdisk, erofs fstab line, **debug logger** as `/init`,
    cmdline `androidboot.selinux_xperms_supported=1 printk.devkmsg=on`)
  - `vendor_b` = `out-plk-debug/vendor.img` (LineageOS 24 vendor, patched; **debug** extras: permissive `kernel` and
    `logpersist` domains, logcat-to-`/metadata` service)
  - `system_b` = `out-plk/system.img` (ColorOS 17 **PLK110 = Qualcomm** Axis GSI, EROFS, patched)
  - `dtbo_b`, `vbmeta_b` = LineageOS 24 (vbmeta flags=3); `abl_b` and all firmware = stock H.40
- **Last observed (this build):** first stage OK, SELinux OK, `/data` metadata+FBE OK, eBPF loaded
  (`bpf.progs_loaded=1`), `netd` running, `system_server` up for 85 s+ — but by 152 s it had **restarted once**
  (pid 2398 → 4293), `sys.boot_completed` never reached 1, and the phone rebooted at ~190 s. ADB is up and
  authorized during boot (this PC's key is baked into the image). Full capture: `logs/plk-build6/live-logcat.txt`.
- **Current blocker (diagnosed, not fixed):** not a crash but a hang — `Watchdog: *** WATCHDOG KILLING SYSTEM PROCESS:
  Blocked in handler on main thread (main) for 69s`. The main thread is stuck in
  `SoundTriggerModule.attachToHal` ← `SoundTriggerMiddlewareService$Lifecycle.onStart` ← `SystemServer.startOtherServices`,
  i.e. waiting on the vendor sound-trigger HAL; at the same moment the vendor audio HAL process crashes
  (`Fatal signal 11 … HwBinder:2770_2 … (audio.service)`; also seen in PLK build 2). The backtrace is not in logcat;
  the tombstone is in encrypted `/data/tombstones` (no adb root on this user build, and Lineage Recovery cannot
  decrypt this `/data`). Next: find which ColorOS audio/sound-trigger client call crashes the LineageOS audio HAL —
  e.g. confirm by disabling the vendor sound-trigger HAL in the debug vendor, or grab the tombstone with
  `adb shell`-readable crash output (`debuggerd` prints a `DEBUG` backtrace to logcat when tombstoned can run).
- **Slot A** = untouched stock ColorOS 12.1 H.40 partitions, but `/data` is the port's → stock A will not boot until
  `/data/reserve/reserve.img` is restored and data is wiped from stock recovery (see §5).
- Bootloader behaviour to remember: after repeated failed boots the A/B logic marks B `unbootable` and **switches to A**
  silently. Always check `fastboot getvar current-slot` / `slot-unbootable:b` and `fastboot --set-active=b`.
  `fastboot reboot recovery` does **not** work on this ABL: enter recovery from the fastboot menu (Vol keys + Power).
  Vol Up + Power = fastboot. Qualcomm `900E` on USB = crash-dump mode after a kernel panic (exit: hold Power+Vol Up
  ~15 s), not a brick.

## 2. What the port is (architecture)

ColorOS 17 *system* on a **LineageOS 24 base** (LineageOS boot/kernel/dtbo/vbmeta/vendor). Reason: Android 17 needs a
4.14 kernel with eBPF backported to 5.10 level plus `ro.bpf.kver_override`, two-stage init, etc. — LineageOS's
`4.14.357-openela` kernel has all of it; stock H.40 does not (see PORTING.md "eBPF wall").

Patches applied by `tools/build-port-b.sh` (each one fixed an observed failure; reasons in comments and PORTING.md):

| Layer | Change | Failure it fixed |
|---|---|---|
| system | EROFS (`-zlz4hc,12 -E legacy-compress`), `my_stock` emptied | size (3.39 GiB partition) |
| system | adb on + `/product/etc/security/adb_keys` = this PC's key | debugging |
| system | `ro.bpf.kver_override=5.10.239` | eBPF kernel gate |
| system | drop property_contexts that vendor defines differently (computed) | property trie FATAL |
| system | strip `auditallowx`/`dontauditx` from system CIL | phh init v29 policy compile |
| system | **bind-mount LineageOS builds of 8 override-aware tethering-APEX components + LineageOS eBPF programs over ColorOS's APEX** (`/system/etc/port-los-tether`, `00-port-netbpfload.rc`) + `init mounton` rules | netbpfload / libnetd_updatable kernel gates; ColorOS eBPF objects hard-reset the kernel; whole-APEX swap broke system_server |
| boot | erofs `/system` line in first-stage fstab | EROFS mount |
| boot | cmdline `androidboot.selinux_xperms_supported=1` (ignored by ColorOS init, harmless) | — |
| vendor | erofs `/system` line in `fstab.qcom` | — |
| vendor | SELinux: rename/drop type clashes, strip xperms from `plat_pub_versioned.cil` (computed) | policy compile |
| vendor | `fileencryption=aes-256-xts:aes-256-cts:v2` (was `ice`) | `Failed to install fscrypt key: Invalid argument` (only LineageOS's vold handles Qualcomm `ice`) |

Not done yet: `my_stock` apps (Contacts, Phone, Gallery, launcher-ish) are **not installed** — planned as
`/data/reserve_cos17/` + one vendor-fstab loop line once the system boots (`out/reserve.img` idea from PLG110 era;
rebuild for PLK110).

## 3. Build pipeline (all in WSL as root)

```bash
# full port build from the Qualcomm donor (≈10 min): writes out-plk/{system,boot,vendor}.img
export GSI=/mnt/c/Users/Han/Project/OnePlus7Port/ColorOS17-PLK110/system.img W=<LOCAL_WSL_PATH> \
       OUT=/mnt/c/Users/Han/Project/OnePlus7Port/out-plk GSI_MNT=/mnt/plk FBE_MODE=standard
bash /mnt/c/Users/Han/Project/OnePlus7Port/tools/build-port-b.sh
# pre-flash checks (must print PREFLIGHT PASS)
OUT=$OUT bash /mnt/c/Users/Han/Project/OnePlus7Port/tools/preflight-b.sh
# debug variant (logger boot + debug vendor): writes out-plk-debug/
SRC_OUT=$OUT DBG_OUT=/mnt/c/Users/Han/Project/OnePlus7Port/out-plk-debug bash /mnt/c/Users/Han/Project/OnePlus7Port/tools/build-debug-b.sh
```

Flash (phone in fastboot, slot B active): `fastboot flash system_b out-plk/system.img`, `boot_b`/`vendor_b` from
`out-plk-debug/` (debug) or `out-plk/` (clean). If only system changed, flash only `system_b`; `/data` can stay.
Changing the FBE policy or the donor needs a fresh `/data`: from Lineage Recovery run `tools/reset-data-keys.sh`
(`adb push` it to `/tmp` **in the same recovery session** — `/tmp` is wiped on reboot).

WSL gotchas: the VM shuts down when idle → **loop mounts vanish**; every script re-mounts what it needs. Run multi-line
WSL work from a script file (`wsl -d Ubuntu -u root -- bash /mnt/c/.../x.sh`): quoting through PowerShell/Git Bash
breaks `$var`, pipes and parentheses. `sed -i` on files inside a mounted image drops the SELinux xattr — always
rewrite in place (`cat new > file`). Scratch: `<LOCAL_WSL_PATH>` (current donor tree + images, 8.8 GB, regenerated by each
build), `<LOCAL_WSL_PATH>` (debug build scratch, regenerated), `<LOCAL_WSL_PATH>` (APEX comparison, deletable). The
Windows file `...\CanonicalGroupLimited.Ubuntu...\LocalState\ext4.vhdx` is ~78 GB; space freed inside WSL is only
returned to C: after compacting it (as admin: `wsl --shutdown`, then `Optimize-VHD -Path <vhdx> -Mode Full` or
`diskpart` → `select vdisk file=<vhdx>` → `compact vdisk`).

## 8. Rollback

- **Back to LineageOS 24 on B:** flash `LineageOS24/payload/system.img` → `system_b`, `LineageOS24/payload/vendor.img` →
  `vendor_b`, `LineageOS24/boot.img` → `boot_b`; Format data in Lineage Recovery.
- **Back to stock H.40 on A:** `fastboot --set-active=a`; temp-boot `tools/magisk/boot-H40-magisk-adbfix.img`
  (`tools/restore-reserve.ps1`) to put `StockRom/H40-images/reserve.img` back at `/data/reserve/reserve.img`, then wipe
  data from **stock recovery** (never `fastboot -w`/`format`: it deletes reserve.img and makes the wrong FS).
