### Pop-up camera does not retract (user-reported on build 13)

- Cause, verified: the motor helper is a **user app** (`/data/app/…/org.lineageos.camerahelper`, UID 10190,
  `flags=0x0`). `android:persistent="true"` (still in its manifest) is honoured only for apps on a system partition.
  ColorOS FastClear killed it: `am_kill … org.lineageos.camerahelper … o-kill(2006) FastClear` at 14:45:08 and
  14:52:21 (after an `am_stop_idle_service` at 14:44:28). With nothing running, the camera stayed up:
  `/sys/class/motor/position` was **0 (up)** at 15:07. Retracted by hand (`echo 0 > direction; echo 1 > enable` →
  position 1). Live leftovers: motor `direction`/`enable` are owned `u0_a190:system 0644`, and the helper app is
  still installed.
- How the two working builds do it (reference per the "check LineageOS first" rule):

  | Build | Who moves the motor | Killable? |
  |---|---|---|
  | LineageOS 24 | `OnePlusCameraHelper`: `/system_ext/priv-app`, `sharedUserId=android.uid.system`, `persistent`, platform-signed; front-camera (ID 1) availability callback → `/sys/class/motor/{direction,enable}`, calibration from `/mnt/vendor/persist/engineermode/hall_calibration` (LOS commit ec6945cce3 moved calibration to vendor init) | No |
  | Stock H.40 | **No app.** `com.android.server.oplus.MotorManagerService` inside system_server (oplus-services.jar) → HIDL `vendor.oplus.hardware.motorcontrol@1.0::IMotorControl` (`/odm/bin/hw/vendor.oplus.hardware.motorcontrol@1.0-service`; nodes chowned system in `init.oppo.vendor.motor.rc`). Camera/SystemUI/Settings are clients via `MotorManager`/`IMotorManager` | No |
  | ColorOS 17 donor | **Server removed**: only the client API is left (`IMotorManager`, `IOppoMotorManager`, `MotorManager$MotorStateChangedCallback` in oplus-framework.jar); `MotorManagerService` exists only as a name string in oplus-services.jar, and the `IMotorControl` client is gone from services.jar (OnePlus 15 has no motor) | — |

- LOS's exact form can't be copied: ColorOS rejects LOS's platform signature, so the helper can't be system UID.
- **Planned fix for build 14 (not started; user approval pending):** `port.MotorBridge` in the existing root stub
  dex (tools/oplus-stubs, started by init like SliderBridge/TouchBinder, so it is not an app process and FastClear
  can't kill it). It does what the LOS helper does: listen to cameraserver for camera ID 1 open/close (100 ms
  debounce as in LOS `CameraMotorService`), write `direction`/`enable`, and calibrate from persist at boot. No node
  chown or app UID is needed (root). Later, optionally: serve ColorOS 17's leftover `IMotorManager` the stock way.
  Then remove the user-app helper and restore node ownership to `system:system 0644`. Drop/fall protection
  (LOS `FallSensorService`) is untested and must not be claimed.
- Until then the camera can be left up after front-camera use: check `/sys/class/motor/position` (0 = up) and
  retract over adb.

### About phone: battery and charging (resolved live, user-confirmed, in build-port-b.sh)

- **"2 mAh"**: Settings `DeviceInfoUtils.getBatteryCapacity()` reads `ro.product.batterycapacity` only on
  "confidential" builds; normally it uses `PowerProfile.getBatteryCapacity()`. The loaded profile was a
  **placeholder** (`dumpsys batterystats --power-profile`: battery.capacity=2.0, every component 0.1), which also
  made battery-usage stats meaningless. ColorOS reads `<partition>/etc/power_profile/power_profile.xml`
  (oplus-framework.jar). Stock H.40 ships this phone's profile in odm and my_product (identical, sha `fbe1bffc…`,
  battery.capacity **4065**, real screen/CPU values). Build: copied into `my_product/etc/power_profile/`.
  The build-13 `ro.product.batterycapacity=4000` line is unused by this page; kept, harmless.
- **"50W 无线闪充"**: app feature `os.charge.settings.wirelesscharging.power` (int 50) plus 4 other wireless
  features in donor `my_product/etc/extension/com.oplus.app-features.xml` and `feature_com.android.battery.xml`.
  H.40 declares no wireless features (OP7 Pro: Warp Charge 30, wired only). Build: those 6 lines removed (asserted).
  Left for later: `com.oplus.fullscene_plc_charge.support` (OnePlus 15 charging feature, not in H.40).
- The wired-charging line and battery type come from `OplusBatteryManager.getChgConfig` → missing AIDL `ICharger`
  (same root cause as the "voltage too high" warning; handoff-2026-10-15 §0).
